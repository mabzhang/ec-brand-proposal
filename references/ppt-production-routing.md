## 目的与进入条件

满足以下任一条件时进入：

- `34-已确认PPT逐页内容.md` 已完成，且用户明确表示每一页内容可以进入生产；
- 用户从中途接入，提供了一份与 `34` 等价的逐页 Markdown：页码连续、内容已经确认、没有悬空占位符，除分页标记外只包含最终会上屏的文字、数字、标注与客户可见来源。

若用户提供的 MD 仍是长文、大纲、混有后台说明或未确认逐页内容，先回到 [方案脉络与逐页 PPT 内容](./proposal-narrative-and-page-script.md)，不把内容问题交给视觉生产解决。

本环节先帮助用户理解两条路线，再根据交付目标、用户偏好和当前工具给出明确推荐。Agent 的能力决定能否直接执行，但不能单独替代对效果、稳定性、格式、成本和资料权限的判断。

## 先确认视觉输入

先检查项目材料中是否已有：

- 客户 PPT、品牌模板或母版；
- 品牌规范、字体、Logo、产品图与版权可用资产；
- 用户希望接近的 PPT、KV、出版物、网站或其他风格参考；
- 明确禁止的视觉方向；
- 交付比例、文件格式、语言、页数与是否需要可编辑文本。

如用户要求高还原、深度视觉或客户风格一致，但没有客户 PPT、模板或调性参考，先邀请用户上传。只有缺少这些材料会造成不可接受的风格偏差时才暂停。

用户没有提供任何视觉信息时不阻塞，直接使用默认视觉：

- `HTML/PDF 路线`：简约、克制、高留白、严格网格、略带文艺与编辑感，使用少量有意义的大图、产品图、人物或场景图形成图文并茂的页面；避免装饰盒堆叠、廉价渐变、模板化卡片和无意义图标。
- `生图路线`：在保持信息清楚的前提下，提供比 HTML 更丰富、更有完成度的视觉方向；优先使用有叙事性的图像、尺度变化、空间层次和统一的艺术指导，不把“丰富”理解成塞满元素。

从参考材料提炼项目自己的视觉原则，不直接复制参考页面。视觉原则至少说明整体气质、色彩依据、字体倾向、图像语言、信息密度、关键资产与不可使用元素。

## 先比较两条生产路线

进入本环节后，先用下面的表格向用户说明区别；可以根据项目具体情况改写措辞，但不得省略关键取舍。

| 对比 | 路线 A：高视觉生图 | 路线 B：稳定 HTML/PDF |
| --- | --- | --- |
| 更适合 | 更重视视觉冲击、图像表现和整套艺术指导 | 更重视中文、数字、页序、版式稳定与快速交付 |
| 实现方式 | 使用当前 Agent 或用户已有的整页生图工具，逐页生成 16:9 幻灯片图像 | 使用 HTML/CSS 排版，渲染检查后导出 PDF |
| 最好具备 | 生图能力；品牌资产；风格参考会显著提高一致性 | 可用字体、Logo、图片与稳定的 HTML/PDF 渲染环境 |
| 无参考时 | 推荐更丰富、好看、图像驱动的方向，并说明默认艺术指导 | 直接采用简约、克制、高留白、略带文艺感的默认视觉 |
| 优势 | 视觉自由度和单页表现上限更高 | 文字准确、层级和版式更可控，修改效率较高 |
| 局限 | 中文、数字、Logo 和产品细节需要逐页复核；初始页面通常不可编辑 | 视觉表达相对克制，复杂艺术化页面上限较低 |
| 试做方式 | 先做两张代表页，确认后再生成全套 | 先做两张代表页，确认后再生成全套 |
| 常见交付 | 整页图像、PDF、图片型 PPTX；需要时再转可编辑 PPT | HTML 源文件、PDF；需要时再转可编辑 PPT |

展示表格后询问：

> 你现在使用什么 Agent 或工具，是否具备生图能力？这次更看重视觉表现，还是文字与版式稳定？如果你没有特别偏好，我会结合现有工具推荐一条，并先做两张样页。

用户选择后继续，不重复解释全部技术细节。若用户没有明确偏好：

- 当前工具能够直接生图，且项目明显依赖强视觉时，推荐路线 A；
- 当前工具没有生图能力、文字与数据较多，或用户只想稳定完成时，推荐路线 B；
- 推荐不是替用户做不可逆决定；先做两张样页就是低成本验证。

当前工具能力、交付格式、第三方成本或客户资料上传权限仍不清楚时，在这里暂停询问最少问题。上述条件都已清楚，且用户已经要求按推荐完成 PPT 或授权 AI 推进全链路时，可以采用推荐路线直接制作两张样页；样页确认仍是批量生产前的硬暂停点。

## 路线 A：高视觉生图

用户选择生图路线后，先判断当前 Agent 能否直接调用生图工具：

- `能够直接生图`：继续在当前项目中协作；
- `不能直接生图，但用户有惯用工具`：生成可复制的生产提示包，让用户把提示、逐页 MD 和参考图一起交给其工具；
- `用户暂时没有工具`：说明可以连接或改用外部生图能力，但涉及安装、账号、费用、授权和客户材料上传时必须由用户决定；也可以随时改选 HTML/PDF 路线。

### 先建立推荐视觉方向

有参考图时，先提炼色彩、字体气质、图像语言、空间、信息密度和不能复制的部分。

没有参考图时不继续追问阻塞。根据品牌、内容和受众提供少量可判断的视觉方向，并明确推荐其中一条。默认方向应比 HTML 更丰富、更有完成度，例如：

- 大幅叙事图像与克制排版结合；
- 具有编辑感的摄影、拼贴、空间或材质层次；
- 图像、标题、数据和产品之间形成明确视觉关系；
- 每页构图有变化，但整套拥有一致的色彩、字体气质和艺术指导。

避免把“更好看、更丰富”做成满屏装饰、无关奇观、过量光效或每页换一种风格。

### 先做两张代表页

不要默认生成前两页。选择两张最能暴露路线优缺点的页面：

1. 一张视觉主导或核心创意页面；项目没有创意模块时，选择最能代表核心结论的一页；
2. 一张文字、数据、图表、Roadmap 或复杂信息较多的页面。

每页只呈现逐页 MD 中已经确认的上屏内容。提示必须区分：

- `上屏内容`：必须准确出现的文字、数字、Logo、产品资产与客户可见来源；
- `后台视觉指令`：页面任务、信息关系、视觉叙事、前后连续性和构图要求，并注明不得渲染成画面文字；
- `整套艺术指导`：风格、色彩、字体气质、图像语言、信息密度与禁止事项。

样页完成后检查中文、数字、Logo、产品细节、信息层级和缩略图重心，交给用户确认。用户可以确认方向、修改方向或切换到 HTML/PDF；没有确认不批量生成。

### 确认后完成整套

用户确认样页后：

1. 按同一视觉系统逐页生成完整 16:9 幻灯片图像；
2. 不让生图模型添加未确认的观点、数字、案例、合作方或品牌承诺；
3. 只重做出现文字、品牌、产品、构图或连续性问题的页面；
4. 将通过检查的页面按页序导出为图片和 PDF；
5. 用户需要时，可组装为每页一张完整图像的 PPTX，并明确它便于播放和换页，但页面内部不可编辑；
6. 用户需要可编辑 PPT 时，继续阅读 [从 PDF 到可编辑 PPT](#从-pdf-到可编辑-ppt)。

当前 Agent 不能直接生图时，交付的生产提示包至少包括：

- 一段整套总提示；
- 视觉参考的使用说明；
- 逐页上屏内容；
- 逐页后台视觉指令；
- 两张样页的优先试做顺序；
- 文字、数字、Logo、产品和禁止臆造的质检要求。

## 路线 B：稳定 HTML 与 PDF

HTML/PDF 不是能力不足时的惩罚性兜底，而是一条独立路线。它适合中文和数字较多、需要快速修改、强调版式稳定，或当前工具没有生图能力的项目。

### 默认视觉

用户没有提供任何视觉信息时，直接采用：

```text
简约、克制、高留白、严格网格
＋略带文艺与编辑感的排版
＋少量大图、产品图、人物或场景图
＋清楚的标题、正文、数据与来源层级
```

默认视觉可以借鉴 Apple 式的留白、秩序、图像尺度和产品叙事，但不复制苹果页面、字体、模板或品牌资产。图像只在帮助理解、建立情绪或证明产品时出现；没有可靠图片时不使用无关图库图填空。

### 先做两张代表页

与生图路线一样，先选择一张视觉主导页和一张复杂信息页完成 HTML 样页，渲染截图并交给用户确认。用户没有视觉参考并接受默认方向时，不再要求额外选择；样页确认后直接完成全套。

### HTML 生产护栏

- 只渲染已经确认的逐页上屏内容，不把方案脉络、页面职责、推导、审核状态或制作提示写进页面；
- 使用离线单文件和本地资产，保持 16:9，一页一个独立 slide，打印时一页对应一张；
- 使用稳定字体和合理的中英文字体回退；
- 图片应来自用户授权资产或可追溯的可靠来源；页面需要显示来源时使用真实链接；
- CSS 服务当前项目的内容与素材，不从其他品牌搬入成品视觉皮肤；
- 内容放不下时回到对应页面删重、拆页或合页，不靠极小字号、隐藏溢出或抽象空话挤进页面；
- 不为填满空白添加装饰盒、无关图片、模板化卡片、假数据或重复文案。

当前环境另行安装了 `brand-visual-research` Skill 时，可以从它的实际安装目录额外读取以下生产限制与质量护栏；不存在时不阻塞，也不得凭旧记忆声称完成外部规则复核：

- `references/html-pdf-production.md`
- `references/quality-gates.md`

必须先解析该 Skill 在当前环境中的真实位置，不得依赖作者本机路径。

只借用限制与质量护栏，不复制该 Skill 的内容规则、页面架构、固定版式、页面类型或视觉模板。

### HTML/PDF 质检

- 每轮渲染所有页面截图并检查接触表，不只检查代码是否运行；
- 检查页序、重复构图、连续密度、意外上下失衡、裁切、字体、背景和品牌一致性；
- 检查图片加载、文本溢出、模块碰撞、页脚碰撞、小字与失效链接；
- 导出 PDF 后核对 HTML 与 PDF 页数、16:9 尺寸、页序、字体、背景、裁切与链接；
- 只修复明确的问题单元，不无故重做已通过页面；
- 最多进行三轮有问题清单的截图驱动修改；连续三次没有实质改善时停止并报告。

完成 PDF 后，若用户需要可编辑 PPT，继续以下选择。

## 从 PDF 到可编辑 PPT

先说明：PDF 保留视觉最稳定，但不等于可编辑。用户可选择：

| 方案 | 更适合 | 能得到什么 | 主要限制 |
| --- | --- | --- | --- |
| 图片型 PPTX | 只需要播放、换页或快速交付 | 每页一张完整图片的 PPTX | 页面内部文字、图片和图层不可编辑 |
| WPS PDF 转 PPT | 图文分区清楚、结构较简单、希望较低成本获得基础可编辑性 | WPS 尝试把文字和图片转换为独立元素 | 复杂视觉、叠层、特殊字体、图表和艺术效果可能错位、合并或仍需重做 |
| Codia NoteSlide | 更重视图层、板块、文字和形状的细致拆分，愿意支付转换成本 | 重建为可编辑 PPTX，可继续在 PowerPoint 等工具中修改 | 按页消耗额度；复杂图表或视觉效果仍可能保留为图片；上传前需确认客户资料权限 |

### WPS 使用提醒

- 官方入口：[WPS PDF 转 PPT](https://pdf.wps.com/convert-pdf-to-ppt/)。
- 先用两张代表页测试文字、图片、字体、图表和图层拆分，再决定是否处理全套。
- 简洁、图文边界清楚的页面通常更适合；复杂视觉页面不能承诺自动拆得干净。
- PDF 转 PPT 在部分版本或场景中可能需要 WPS 会员，以用户当时看到的官方功能与价格为准。
- 内部低成本提示：淘宝、闲鱼等平台可能出现短期会员、兑换码或代开服务。它们不是 WPS 官方保证渠道；只考虑能在本人账号完成正规兑换或激活、且不要求提交账号密码的方式。不要使用共享或租用账号，不把客户文件交给卖家，并明确存在失效、售后、账号和合规风险。

### Codia 使用提醒

- 官方入口：[Codia NoteSlide](https://codia.ai/noteslide)。
- 更适合用户希望获得更细的板块、文字、形状和图层拆分，而不仅是外观近似的情况。
- 先用免费试转换或少量代表页验证中文、字体、图表、Logo、产品和复杂视觉的拆解效果，再决定是否购买额度处理全套。
- 说明费用按当时官方页面为准，不承诺固定价格。
- 使用第三方服务前，确认用户有权上传客户材料；未经授权不代为注册、充值或上传。

不要把 WPS 说成一定便宜且完美，也不要把 Codia 说成一定能拆开所有图层。两者都是转换路线，样页测试结果比工具宣传更能决定是否适合当前项目。

## 共同质检与交付

无论选择哪条路线，都要检查：

- 页数、页序和章节与 `34` 或等价逐页 Markdown 一致；
- 除逐页 Markdown 明确写入的上屏内容外，没有出现页面职责、客户问题、推导过程、制作提示、内部来源路径、前后衔接或审核状态；
- 每页主要结论可在正常阅读距离识别；
- 文字、数字、品牌名、产品名、Logo 和引用没有错误；
- 没有生成不存在的产品、合作方、奖项、数据或客户承诺；
- 风格在整套中一致，但不是机械重复同一构图；
- Roadmap 与 `30` 的逻辑、阶段、媒介分工和依赖一致；
- 关键页面在缩略图状态仍能看出视觉重心；
- PPTX、PDF、整页图像与源文件路径可追溯。

把用户看到的路线对比、用户选择、工具与能力、默认或已选视觉方向、两张样页反馈、版本、逐页问题、修改记录、最终文件路径、PDF 转 PPT 选择和仍存在的限制写入 `35-PPT生产与交付记录.md`。

最终交付先说结果，再链接文件，并明确：

- 使用了哪条生产路线；
- 交付了哪些格式；
- 哪些内容仍是占位、假设或需要客户确认；
- 生图、PDF 或转换路线下的可编辑性限制；
- 是否已经完成逐页视觉与导出文件复核。

## 边界与停止条件

- `34` 或等价逐页 Markdown 未确认时不进入生产。
- 不只根据 Agent 能力替用户强制选择路线；先呈现取舍并给出推荐。工具、格式、成本或权限不清楚时等待用户，条件清楚且已有按推荐推进的授权时可直接进入样页。
- 用户没有视觉参考时不停止：按所选路线使用本文件规定的默认视觉。
- 两张代表性样页没有确认时，不批量生成整套。
- 不未经授权连接、购买、安装第三方服务或代用户付款。
- 用户未授权时，不向第三方上传客户机密材料。
- 生产阶段不得悄悄改变策略、创意、媒介或逐页内容。
- 外部转换工具的功能、价格和效果会变化；使用前以当时官方信息和当前项目样页测试为准。
- 三次连续修改没有实质改善时停止，报告具体问题并请求用户决定降级、换路线或补充素材。
