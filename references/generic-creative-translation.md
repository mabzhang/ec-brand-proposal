## 目的与进入条件

当已经确认的 Campaign 表达宪法与落地安排确定一项创意任务，但该任务没有 KV、TVC、事件营销或其他专门参考模块时，使用本协议。该确认可以记录在 `18-已确认Campaign落地安排.md`，也可以来自中途接入时经本轮确认的等价材料。

用户直接要求代言人、IP、联名、包装、门店、社交、KOL、CRM、产品体验或技术互动等单项创意时，先回到 [Campaign 表达宪法与落地安排](./campaign-expression-and-architecture.md)，确认该任务为什么存在、独自负责什么及不能破坏的表达边界，再进入本协议。

可处理代言人、文化人物、IP合作、品牌联名、包装、门店、渠道、社交互动、KOL内容、会员与CRM、产品体验、数据或技术互动等尚未专项化的任务。

本协议不重新决定 Campaign 要做什么，只回答：

> 已经确定要做这件东西以后，怎样让它用自身最擅长的方式承接核心创意基础？

如果某项任务已有专门模块，优先读取专门模块，不用通用协议覆盖更具体的方法。

## 读取已定任务

读取可用的 `17`、`18`、实际存在的 `16` 或等价确认材料，以及该任务相关的 Brief、预算、资源、渠道、人物、产品和限制。核心创意基础可以是正式 Big Idea，也可以是经确认的最小创意基础。先确认：

- 这项内容独自负责什么；
- 主要面对谁、出现在哪里；
- 希望人理解、感受或做什么；
- 其他已选内容已经承担什么；
- 哪些品牌资产和表达边界必须继承；
- 当前预算与资源允许做到什么程度。

用一句后台任务定义开场：

```text
这项内容不负责重复整个核心创意，
它主要通过____，
让____在____场景中
理解、感受或完成____。
```

只有发现 `18` 的任务本身互相冲突、缺乏必要资源或无法承接表达宪法时，才回到 `17`、`18`；不要把例行创意开发变成重新规划内容组合。

## 通用创意母链

按以下顺序推导：

```text
已确定的单项任务
→ 载体原生能力
→ 核心承载资产
→ 创意生成动作
→ 用户体验结果
→ 品牌与产品因果
→ 不同方向
→ 用户选择
```

通用公式：

```text
创意方向
＝单项任务
＋载体原生能力
＋核心承载资产
＋创意生成动作
＋用户体验结果
＋品牌与产品因果
```

预算、资源、合规和执行条件用于筛选方向，不取代创意原点。

## 识别载体原生能力

先问：

> 只有这种载体，才能让什么事情发生？

不要只把核心创意印、拍或贴到载体上。

| 任务或载体 | 可利用的原生能力 |
| --- | --- |
| 代言人或文化人物 | 既有公众人格、真实经历、社会关系、信任和持续行动 |
| IP或品牌合作 | 两套角色、世界观、产品能力、渠道与人群可以建立新关系 |
| 包装 | 进入货架、购买、携带、开启、使用、保存和分享过程 |
| 门店或空间 | 改变人的路径、服务、停留、互动与现场关系 |
| KOL或社交内容 | 依靠具体视角、圈层语言、回应、模仿、接力和改编扩散 |
| 会员与CRM | 根据身份、关系和长期行为提供连续、差异化反馈 |
| 产品或服务体验 | 直接改变使用过程、行为结果和相信理由 |
| 数据或技术互动 | 感知输入、即时计算、个性化反馈并持续生成结果 |

这张表只是示例。面对新任务时，从其真实使用过程、关系和物理或数字特性重新判断，不按示例硬套。

代言人不只是露面，包装不只是印文案，门店不只是装修，社交不只是发布帖子。若没有使用载体原生能力，优先重做。

## 选择核心资产与创意动作

选择最有资格承载表达的核心资产，可能是：

- 人物的真实经历、公众标签或关系；
- 产品形态、功能、使用结果或服务能力；
- 具体行为、场景、物件或语言；
- 品牌符号、数据、会员、渠道或技术资产；
- 合作方的角色、产品、渠道或文化意义。

然后确定创意生成动作：

> 准备对核心资产做什么，才能让核心创意变成这种载体中的体验？

可以探索赋予角色、建立关系、开放决定权、显现、隐藏、拿走、改变使用方式、共同完成、持续回应、形成仪式、交换能力或让结果随参与变化等动作，但不要逐项填表。

创意动作相当于：

- KV 的视觉动词；
- TVC 的影片发生规则；
- 事件营销的品牌真实动作。

不同方向的差异应来自原生能力、核心资产或生成动作，而不是明星名字、平台、场地、美术风格或情绪语气。

## 定义用户体验与品牌因果

检查用户端：

```text
用户最先遇到什么
→ 为什么继续看、使用或参与
→ 中间发生什么变化
→ 最后理解、感受或获得什么
→ 是否进一步使用、分享或行动
```

再检查品牌因果：

- 为什么品牌有资格这样做；
- 产品、人物或品牌能力是否进入创意因果；
- 换成竞品是否仍然完全成立；
- 是否只是借用热门人物、IP、技术或形式；
- 是否忠于表达宪法和该内容的单项任务。

若用户体验成立但品牌可以任意替换，回到核心资产与创意动作。

## 后台生成与筛选方向

先在后台生成更宽的方向池，再归并、反证和淘汰。成立多少保留多少，不固定数量。

每个后台方向检查：

1. 单项任务与目标人群；
2. 载体原生能力；
3. 核心承载资产；
4. 创意生成动作；
5. 用户接触与变化；
6. 品牌和产品因果；
7. 与 KV、TVC、事件或其他内容的关系；
8. 预算、资源和现实条件；
9. 误读、合规、伦理和执行风险；
10. 是否值得升级为一个可讨论的方向。

删除：

- 只是把口号搬到新载体；
- 只更换人物、平台、场地或风格；
- 没有利用载体原生能力；
- 用户只能被动观看，却被描述成参与；
- 品牌与产品最后后贴；
- 与已有专业内容重复；
- 预算只能完成外壳，无法完成核心动作；
- 需要长篇解释才能明白准备做什么。

把完整推导、候选池、淘汰原因和保留方向保存或更新到 `25-扩展创意任务方向工作台.md`。存在多个未专项化任务时，为每项任务建立独立章节，一次只推进一个选择点。

## 前台精炼交付

完成后台工作后，先用一小段话说明这项任务独自负责什么，以及为什么应该这样使用这种载体。随后逐个方向直接说准备做什么，再用两三句话让用户看见核心资产、创意动作和用户会经历什么。标题、段落或短列表按内容自然选择，不强制每个方向使用同一套字段或相同长度。最后必须明确推荐一条或一种组合，并说明它为什么最能完成该载体的独立任务。

不要向用户展示通用公式、完整候选池、验算表或后台风险清单。只有会改变选择的现实条件，才用一句话补充。

结尾先给出推荐，再询问：

> 基于当前任务和上下游分工，我建议优先采用____，因为____。如果你没有异议，我会按这个方向继续；你也可以组合、修改或要求换角度。

多条路线会显著改变核心资产、用户经历、品牌角色或资源重心，且 AI 推荐仍不能消解分歧时暂停。只有一条明显成立，或用户已要求按推荐完成下游、说过“继续”“按你的建议做”“完整做完”时，可采用推荐继续。没有选择、没有预先授权且推荐无法消解重大分歧时，不生成唯一方向。

## 讨论、记录与模块升级

用户选择、组合、修正，或依据预先授权采用推荐后，更新 `26-已选扩展创意方向.md`。多个任务仍按任务分节；每节先用自然摘要说明最终决定、采用方式与原因，再保留后续工作真正需要的信息：

- 任务名称和独自承担的作用；
- 已选方向与用户修正；
- 核心资产和创意动作；
- 用户最终会经历什么；
- 品牌与产品不能被破坏的因果；
- 当前预算下必须保住的核心；
- 仍会使方向失效的关键条件；
- 选择和放弃原因。

写完后返回主状态路由：最终目标就是当前扩展创意方向时停止；`18` 还有其他 `required` 且未完成内容时继续相应模块；内容模块全部完成后，媒介与 Roadmap 为 `required` 时进入传播路径与 Roadmap，为 `not_required` 时进入最终目标所需的方案或交付环节。

某类任务后来形成稳定、具体且反复使用的方法时：

1. 为它新增独立参考模块；
2. 在主状态路由中让专门模块优先；
3. 保留本协议作为未专项化任务的后备接口；
4. 不因新增专门模块改写既有项目的历史选择。

## 边界与回退

用户认为扩展创意方向不对、补充新想法或要求换角度时，先进入聊天探索。以下各项只帮助判断问题位于 Campaign 分工、创意基础还是载体转译；在用户明确收束前，不修改 `17`、`18`、`25`、`26` 或任何上游文件。聊清楚后再按明确指令一次性更新。

- 不在这里重新选择 Campaign 内容组合；
- 不用通用协议替代已经存在的专业模块；
- 方向无法承接核心创意基础或表达宪法时，回到 `17`—`18`；用户需要重新探索 Big Idea 时才回第三阶段；
- 与其他内容任务重复或单项任务错误时，回到 `17`、`18`；
- 载体、人物、合作方、预算或资源变化时，先在聊天中重想受影响方向；
- 用户要求完整制作、执行或媒介方案时，先完成并确认当前方向，再进入后续专业模块；
- 本协议完成方向选择，不自动生产未知任务的所有执行细节。
