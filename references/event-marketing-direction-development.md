## 目的与进入条件

只有已经确认的 Campaign 表达宪法与落地安排明确需要事件营销、品牌行动、公众参与、线下体验、创意商业或事件化媒介时才进入。该确认可以记录在 `18-已确认Campaign落地安排.md`，也可以来自中途接入时经本轮确认的等价材料。

用户直接要求事件方向时，先回到 [Campaign 表达宪法与落地安排](./campaign-expression-and-architecture.md)，确认品牌准备证明什么、事件独自承担什么任务，以及预算、资源和现实边界；不要直接用活动形式代替事件命题。

本模块只完成事件方向共创：

1. 在后台基于表达宪法、Brief、预算、资源和事件母型充分推导；
2. 向用户只呈现一段精炼判断，以及少量真正不同的方向；
3. 每个方向只讲清品牌准备做什么、可以怎么做；
4. 给出 AI 推荐；用户选择、组合、修正，或依据预先授权采用推荐后记录已选方向；
5. 最终目标就是事件方向时停止，否则返回主状态路由继续完成已声明的下游。

不在这里继续写完整事件执行方案、场地设计、活动流程、人员分工、供应商清单、详细预算、传播排期或现场手册。

事件不等于办活动。判断重点是：

> 品牌究竟准备让什么在现实中发生，它会产生什么可见结果，以及为什么只能或最适合由这个品牌发起？

## 读取上游与明确事件任务

读取可用的编号文件或等价确认材料：

- `12-已选策略方向.md`；
- `13`—`18`；
- Brief 已规定的事件形式、节点、地点、渠道、人物、合作伙伴和必须交付项；
- 总预算、预算等级、资源投入和制作限制；
- 品牌现有产品、门店、平台、会员、IP、人物、渠道、技术、服务与商务能力；
- 已完成的 KV 或 TVC 方向，避免内容任务重复；
- 事件涉及的安全、合规、伦理、舆情与持续运营条件。

先写一句后台事件任务：

```text
这次事件不是为了制造热闹，
而是要让____在现实中发生，
从而证明品牌所说的____，
并推动____发生变化。
```

若无法从表达宪法和 `18` 得到清楚任务，先回到 `17`—`18` 补齐最小创意基础与任务，不要用快闪、装置、明星或话题掩盖问题。

Brief 已经规定线下活动、发布会、代言人或地点时，不制造是否要做的假选择；围绕仍开放的真实动作、参与机制和传播证据提出方向。

## 把核心表达转成现实动作

事件方向的核心转译是：

```text
品牌想表达什么
→ 品牌愿意为此做什么
→ 谁会因此做出什么行动
→ 现实中会产生什么变化
→ 公众能看到什么证据
→ 这个结果怎样回到品牌、产品或生意任务
```

用事件命题帮助后台检查：

```text
为了让【目标人群】
从【当前状态】变成【希望状态】，
品牌决定【真实行动】，
邀请【参与角色】通过【发生机制】共同完成，
最终产生【可见结果】，
以此证明【品牌回答】。
```

事件命题是工作工具，不要求原样展示给用户。若必须依赖长篇解释才能明白品牌做了什么，说明方向仍不清楚。

## 选择事件母型

事件母型回答：`这件事主要靠什么现实机制成立？`

以下母型只供后台发散、归并和反证，不让用户从类型清单中作答：

| 事件母型 | 核心改变 | 基本发生链 |
| --- | --- | --- |
| 真实行动与服务型 | 现实问题、流程或服务体验 | 具体阻力 → 品牌能力介入 → 可使用服务 → 真实结果 → 反馈与持续 |
| 用户共创与资产生成型 | 产品、内容、规则或品牌资产 | 开放资产 → 低门槛创作 → 共创与选择 → 专业化 → 正式采用与使用 |
| 公共仪式与好戏型 | 参与身份、社会关系或公共观看 | 公共时机 → 文化原型 → 世界规则 → 角色行动 → 真实互动 → 仪式收束 |
| 产品事实与公开证明型 | 产品认知与相信理由 | 隐藏事实 → 放大、拆解或演示 → 公共证明 → 见证与讨论 → 产品归因 |
| 空间与现实场景介入型 | 特定地点中的情绪、关系或体验 | 真实场景 → 精准地点 → 物件或设施介入 → 遭遇与使用 → 可见变化 |
| 利益转移与促销游戏型 | 资源、权益和消费者利益关系 | 公共节点 → 资源选择 → 真实利益 → 参与规则 → 结果推进 → 权益兑现 |
| 消费场景与创意商业型 | 购买、使用或消费习惯 | 新使用场景 → 必要商品或物件 → 合作与渠道 → 发现购买使用 → 分享与转化 |

方向可以组合母型，但必须有一个主发生引擎。明星、快闪店、IP、装置、联名、KOL、热搜和UGC是资源、形式或结果，不是充分的事件母型。

判断事件强度：

- 有没有真实行动和现实后果；
- 用户是参与者、使用者、受益者、创作者还是仅仅围观；
- 有没有可被看见、使用或验证的证据；
- 品牌与产品是否不可替换；
- 事件结束后是否留下服务、资产、行为、关系或商业结果。

事件化户外或产品装置可以成立，但不要因为它能拍照传播，便夸大成强参与事件。

## 寻找创作角度

同一个核心表达可以从不同角度变成事件：

- `人的困境`：品牌直接解决或缓解一个具体阻力；
- `产品事实`：让产品能力被公众亲眼看见或验证；
- `品牌选择`：品牌愿意投入、改变、开放或放弃什么；
- `人群表达欲`：让用户共同创造并影响最终结果；
- `文化时机`：创造新的公共仪式、角色或好戏；
- `具体场景`：改变问题发生的空间、流程或物件；
- `商业链路`：让商品、合作伙伴和渠道共同推动新使用行为。

创作角度用于后台形成不同因果，不作为前台标签。不要把线上、线下、明星、装置、温暖、幽默当成方向差异。

## 后台生成与筛选方向

先在后台建立更宽的方向池，再归并、反证和淘汰。成立的方向有多少就保留多少，不为数量凑数。

每个后台方向检查：

1. `事件任务`：准备解决什么。
2. `核心表达`：承接表达宪法中的哪一条。
3. `创作角度与主母型`：从哪里切入，靠什么成立。
4. `一句话事件事实`：品牌真的准备做什么。
5. `发生机制`：怎样持续发展，而不是开幕即结束。
6. `角色`：品牌、核心人群、伙伴、公众分别做什么。
7. `可见结果`：什么变化能够被使用、验证或见证。
8. `传播证据`：什么瞬间、物件、人物、数据或结果值得转述。
9. `品牌与产品因果`：为什么不能轻易换成竞品。
10. `预算与资源条件`：核心动作是否能够被诚实完成。
11. `后续价值`：留下服务、资产、行为、关系还是商业结果。
12. `风险`：执行、安全、合规、伦理、舆情和虚假承诺。

删除：

- 只有活动主题，没有真实动作；
- 只是快闪、装置、明星或联名的物料组合；
- 参与者只能围观、打卡或转发，却被包装成共创；
- 传播完全依赖媒体通稿，没有自身证据；
- 现场热闹但离开现场便无法解释；
- 品牌只提供赞助或最后贴 Logo；
- 所谓行动没有实际兑现能力；
- 多个方向只是更换场地、人物、媒介或语气；
- 预算只能支持外壳，无法完成核心机制。

把完整推导、候选池、淘汰原因和保留方向保存为 `23-事件营销方向候选工作台.md`。工作台可以详细，但不要把它原样复制到聊天。

## 结合预算与资源

预算用于判断事件能否真实发生，不用于决定核心表达值不值得做。

后台区分：

- 必须保住的核心动作；
- 当前预算下可诚实完成的最小规模；
- 预算增加后可以扩大的人群、地点、周期或传播范围；
- 品牌已有且可以调用的非现金资源；
- 真实发生、现场运营、内容记录和传播放大的资源分配；
- 一次性制作与持续服务的成本差异。

不要把预算全部花在现场，却没有使用结果或传播证据；也不要为拍摄一条漂亮 case video，牺牲事件本身。

预算或资源会直接改变用户选择时，在前台用一句话说明成立条件；否则留在后台。

## 前台精炼交付

用户只需要迅速看懂：

1. 一段`我们怎么理解这次事件`；
2. 少量真正不同的事件方向；
3. 每个方向的`做什么`和`可以怎么做`；
4. AI 明确推荐哪一个或怎样组合，以及为什么；
5. 一句邀请用户判断、组合或修正的话。

前台不要展示：

- 七种事件母型清单；
- 完整事件命题模板；
- 角色图、发生链和传播链；
- 候选池、淘汰过程和评分模型；
- 大段预算、风险与执行分析；
- 为显示专业而堆砌的案例和方法论。

先用一小段人话说明“这次事件真正要让什么发生，为什么值得从这些方向做”。随后逐个方向直接说品牌准备做什么，再用两三句话让用户看见核心动作、发生场景和参与方式。标题、段落或短列表按内容自然选择，不强制每个方向使用同一套字段或同样长度。

方向数量不固定。不要固定写成三个，也不要为完整感展示不足以成立的路线。

只有某项依据或限制会改变选择时，才补一小句`为什么适合`或`成立条件`。方向之间的差异必须能从“品牌做了不同的事”被直接感知，不要求用户理解专业分类。

交付结尾先给出推荐和取舍理由，再问：

> 基于当前目标和条件，我建议优先采用____，因为____。如果你没有异议，我会按这个方向继续；你也可以组合、修改或要求换角度。

## 讨论、选择与文件产出

完成 `23` 后，在聊天中交付上述精炼版本。存在多条会显著改变事件事实、参与机制、品牌角色或资源重心的成立路线，且 AI 推荐仍不能消解分歧时暂停，允许用户：

- 选择一个方向；
- 组合多个方向的核心动作；
- 修改事件动作、参与方式或发生场景；
- 指出某个方向不真实、不像品牌或做不了；
- 补充预算、资源和组织限制；
- 要求换角度重做。

只有一条明显成立，或用户已要求按推荐完成下游、说过“继续”“按你的建议做”“完整做完”时，可采用推荐并继续。没有选择、没有预先授权且推荐无法消解重大分歧时，不展开唯一方向。

用户选择、修正，或依据预先授权采用推荐后写 `24-已选事件营销方向.md`。先用自然摘要记录最终决定、采用方式和选择原因，再保留后续执行真正需要的内容：

- 已选方向和一句话事件事实；
- 用户组合与修正；
- 事件准备让什么真实发生；
- 核心动作和必要的参与方式；
- 品牌与产品不能被破坏的因果；
- 当前预算下必须保住的核心；
- 仍会使方向失效的关键条件；
- 选择与放弃原因。

写完后返回主状态路由。最终目标就是事件方向时停止；若 `18` 还有其他 `required` 且未完成的内容模块，继续相应模块；内容模块全部完成后，媒介与 Roadmap 为 `required` 时进入传播路径与 Roadmap，为 `not_required` 时进入最终目标所需的方案或交付环节。

## 边界与回退

用户认为事件方向不对、只像形式或补充新想法时，先进入聊天探索。以下各项只帮助定位需要重想的层级；在用户明确收束前，不修改 `17`、`18`、`23`、`24`，不撤销文件状态，也不生成新版本。聊清楚后再按明确指令一次性更新。

- 方向只有形式，没有真实动作：在聊天中重想角度和事件命题。
- 方向无法承接核心创意基础或表达宪法：回到 `17`—`18`；用户需要重新探索 Big Idea 时才回第三阶段。
- 与 KV、TVC 或其他内容任务重复：回到 `17`、`18` 重新分工。
- 预算、资源、地点、人物或合作条件改变：先在聊天中重算 `17`、`18` 所代表的安排和方向。
- 用户选择后发现核心机制失效：先在聊天中说明原路线为何失效并发展新方向；用户明确收束后，再一次性记录原因、撤销 `24` 的确认状态并更新文件。
- 用户要求完整事件执行方案：先完成并确认 `24`，再进入独立后续模块；不把执行内容混入本模块。
